## The SO-101 Robot Arms 
{: .no_toc }

For this module, we will be writing code to calculate the inverse kinematics for our SO-101 robot arms using a geometric approach. We will derive the solution, verify it in simulation, verify it on hardware, and then use it to repeat the same "Pick and Place" maneuver from Lab 6 but without needing pre-determined joint configurations. The goal is to pick up two separate blocks and stack them on top of each other using a single inverse kinematics function that you build up throughout this module.

## Assignment Part 1: Derive the Inverse Kinematics

### 1a) Set up Inverse Kinematics Functions
First, write a helper script named `so101_inverse_kinematics.py` that takes in a desired tool frame position and orientation and returns the corresponding joint configuration.         'wrist_flex': 0.0,

        'gripper': 0.0

Next, we need to account for where the block sits relative to the end-effector frame, which requires two offsets:

- **In the x-direction:** For a vertical grasp, the tool frame is aligned with the world frame, and the fixed jaw is on the $-x$ side of the end-effector frame, a distance $d = 0.0079$ m from the wrist roll axis. The fixed jaw does not move, so it needs to line up with the $-x$ edge of the block.
- **In the z-direction:** The end-effector frame is located at the tips of the jaws. If we sent this frame to the center of the block, the jaws would only reach the middle of the block. Lowering the target by half of the block height lets the jaws surround the block.

Since our blocks are cubes with width $w$, the target position that we send to our inverse kinematics is:

$$ p_{target} = p_{block} - \begin{bmatrix} w/2 - d \\ 0 \\ w/2 \end{bmatrix} $$

Add the following helper function to your `so101_inverse_kinematics.py` script. Whenever we want to reach a block, we will specify the center of the block and use this function to compute the end-effector target. If the fixed jaw clips the block as it moves down, slightly increase the x offset.

```python
BLOCK_WIDTH = 0.0285  # meters (1.125 inches)
FIXED_JAW_OFFSET = 0.0079  # meters, from the wrist roll axis to the inner face of the fixed jaw

def get_gripper_target(block_position):
    "Offset from the center of the block so that the jaws surround the block"
    gripper_target = list(block_position)
    gripper_target[0] -= BLOCK_WIDTH / 2 - FIXED_JAW_OFFSET
    gripper_target[2] -= BLOCK_WIDTH / 2
    return gripper_target
```

### 3d) Check Tracking Error
If you are still having trouble getting accurate positioning even after recalibration, you can check if your error is due to a tracking error through plotting the desired and actual states during the movement. For example, you can create a new `move_to_pose_with_logging` function call that does the following:

```python

import pandas as pd
def move_to_pose_with_logging(bus, desired_position, duration):
    start_time = time.time()
    starting_position = bus.sync_read("Present_Position")
    
    # Initialize log fields
    times = []
    targets = []
    actuals = []
    joint_names = list(desired_position.keys())
    
    while True:
        t = time.time() - start_time
        if t > duration:
            break

        # Interpolation factor [0,1] (make sure it doesn't exceed 1)
        alpha = min(t / duration, 1)

        # Interpolate each joint
        position_dict = {}
        for joint in desired_position:
            p0 = starting_position[joint]
            pf = desired_position[joint]
            position_dict[joint] = (1 - alpha) * p0 + alpha * pf

        # Send command
        bus.sync_write("Goal_Position", position_dict, normalize=True)

        # Store Actual Position
        present_pos = bus.sync_read("Present_Position")
        
        # Log time, target, and actual
        times.append(time.time())
        targets.append([position_dict[j] for j in joint_names])
        actuals.append([present_pos[j] for j in joint_names])

        # Sleep to achieve 50 Hz control loop
        time.sleep(0.02) 
        
    # Convert to DataFrame
    df = pd.DataFrame({
        "time": times,
        **{f"target_{j}": [t[i] for t in targets] for i, j in enumerate(joint_names)},
        **{f"actual_{j}": [a[i] for a in actuals] for i, j in enumerate(joint_names)},
    })
    
    return df
    
```

## Suggested Improvements 
There are a few things that we can do to improve the tracking performance during our pick-and-place maneuver.

### Adding Starting Configuration to `move_to_pose`
One suggestion is to modify the `move_to_pose` helper function to take in a desired starting location rather than taking the readings from the encoders as the starting location. This will reduce the discontinuity that occurs from the steady-state error.

```python

def move_to_pose(bus, starting_position, desired_position, duration):
    start_time = time.time()

    while True:
        t = time.time() - start_time
        if t > duration:
            break

        # Interpolation factor [0,1] (make sure it doesn't exceed 1)
        alpha = min(t / duration, 1)

        # Interpolate each joint
        position_dict = {}
        for joint in desired_position:
            p0 = starting_position[joint]
            pf = desired_position[joint]
            position_dict[joint] = (1 - alpha) * p0 + alpha * pf

        # Send command
        bus.sync_write("Goal_Position", position_dict, normalize=True)

        # (Optional) Read back
        present_pos = bus.sync_read("Present_Position")
        print(present_pos)

        time.sleep(0.02)  # 50 Hz loop
```

{: .note}
> This change will need to be propogated through the rest of your code. Everywhere that you call `move_to_pose` you will need to also provide the desired starting configuration of your motion. Since this is a fairly large change, I recommend implementing it in simulation first.
